# Security

B1 AI Hub is LAN-only by default. Do not expose it through router port forwarding.

Controls implemented or planned:

- HTTPS via Caddy, defaulting to the internal LAN CA while allowing externally supplied certificate files through `B1_CADDY_TLS_ARGS` and a read-only `$B1_DATA_ROOT/secrets/caddy-certs` mount
- persisted CORS allowlists with no wildcard credentialed origins
- secure session cookies and CSRF protection for browser mutations
- local browser passwords stored as scrypt hashes
- role checks and per-key scopes
- API keys stored as salted PBKDF2 hashes with one-time display of the full key
- bootstrap administrator key generated outside Git under `$B1_DATA_ROOT/secrets`
- AES-GCM encrypted configuration-secret storage backed by `$B1_DATA_ROOT/secrets/master_encryption_key`
- SSRF protection for model imports and generic runtime URLs
- archive traversal, symlink/device-node refusal, denied executable/code file types, and zip-bomb limits
- path canonicalization for artifacts and blobs
- no prompts, voice samples, bearer tokens, or documents in logs
- pinned ComfyUI custom nodes
- disabled cloud providers and telemetry by default

The runtime-agent API is intentionally narrow. It is the only service that mounts `/var/run/docker.sock`; the control plane does not mount the Docker socket. Bootstrap generates `$B1_DATA_ROOT/secrets/runtime_agent_token`, a private runtime-agent CA, a runtime-agent server certificate, and a control-plane client certificate. Compose mounts those files read-only at `/run/secrets/*`. The default runtime-agent URL is `https://runtime-agent:8443`, Uvicorn requires a client certificate signed by the generated CA, and all runtime-agent `/v1/*` endpoints still require `Authorization: Bearer <token>` when that secret is present.

The control plane emits structured JSON logs through a single `log_event` helper. That helper recursively redacts sensitive keys such as prompts, messages, inputs, media, voice samples, documents, tokens, credentials, cookies, passwords, and API keys; it also redacts bearer-token strings, B1 API-key strings, GitHub PAT-shaped strings, and sensitive URL query parameters before writing to stdout/stderr. Long strings and long lists are bounded so logs cannot become a prompt or upload exfiltration path.

The implemented runtime-agent surface validates service names against immutable allowlists, reports Docker/service status, retrieves bounded Docker logs with B1 API keys and bearer tokens redacted, and exposes start/stop/restart only for allowlisted B1 AI Hub services. Browser log access goes through `GET /admin/services/{service}/logs`, which adds administrator/operator authorization, a fixed service allowlist, a 500-line cap, and a second redaction/truncation pass before returning entries to Control Center. Predefined runtime `recover` and `unload` actions are restricted further by `B1_RUNTIME_ACTION_SERVICES` and currently map to bounded restarts of those runtime services. Update image inspect/pull endpoints accept only allowlisted services and image references pinned by `@sha256:<digest>`; `latest` and missing digests are rejected before Docker is contacted, and a real pull fails unless Docker inspection confirms the requested digest. Predefined rollback is restricted to the static `B1_ROLLBACK_SERVICES` restart plan; clients cannot submit arbitrary services, commands, environment variables, or mounts. Mutations remain disabled unless `B1_ENABLE_MUTATIONS=true` is set explicitly. Arbitrary commands, environment variables, mounts, container creation, exec, file writes, and Docker API passthrough are forbidden.

Artifact downloads are authorized by the control plane. An artifact path must normalize under `/artifacts`, must be present on a durable job record, and must belong to the requesting API client unless the caller has administrative wildcard scope. The artifact-server remains internal-only and also requires the generated `B1_ARTIFACT_SERVER_TOKEN_FILE` bearer token on artifact and Model Hub blob routes; only `/healthz` is unauthenticated for Docker health checks.

Media job visibility is owner-scoped on ordinary `/v1/media/jobs` routes. A service, creator, or user API key with `jobs:read` can list/read/cancel/event-stream only its own jobs unless it has wildcard administrative scope. Whole-system queue inspection and mutation use `/admin/jobs`, require `admin` or `operator` role, and audit priority, cancel, and retry mutations without storing prompts or media in audit metadata.

Voicebox profile management is limited to `admin` and `operator` roles with runtime scopes. Profile metadata is JSON-size bounded and rejects inline audio/base64 payloads, local paths, secrets, prompts, and voice sample fields. Reference samples and cloned-voice material must be stored as artifacts and linked by normalized `/artifacts/...` references. Create, update, export, and soft-delete operations write audit events that include only public profile identifiers and counts, not raw audio or sample hashes.

API clients can be constrained by a stored CIDR allowlist that is enforced during bearer-token authentication and updated without rotating key material. Dedicated Model Hub clients are additionally constrained by their stored model allowlist, download permission, CIDR allowlist, and blob-download rate limit. The Model Hub CIDR check is applied to catalog, model, sync-plan, and blob routes, and the backing API key also carries the same CIDR list for early authentication rejection; CIDR updates keep those records synchronized. Forwarded client IP headers are trusted only when the direct peer is inside the active trusted proxy CIDR policy; otherwise the direct peer address is used so clients cannot spoof their source address through headers. CORS uses the same persisted network-policy row and permits credentialed browser calls only from explicit canonical origins, never `*` or `null`. Resetting the policy returns to `B1_CORS_ALLOW_ORIGINS` and `B1_TRUSTED_PROXY_CIDRS`. `GET` and `HEAD /modelhub/v1/blobs/{sha256}` use `B1_MODELHUB_BLOB_REQUESTS_PER_MINUTE` as a Redis-coordinated fixed window per authenticated subject and client address; if Redis is unavailable, the control plane falls back to a bounded in-process window so a single process still fails closed with HTTP 429 instead of bypassing limits.

Inference runtimes do not mount the full authoritative model library. LocalAI, ComfyUI, Voicebox, and CPU audio receive only `$B1_DATA_ROOT/models/runtime-views/{runtime}` as read-only `/srv/b1-ai-hub/models`. The control plane creates those views from already verified blobs and refuses symlinked view paths, so a runtime cannot browse or mutate unrelated model blobs.

The first model download worker accepts only HTTPS direct URLs and Hugging Face repository URLs, rejects private/loopback IP literals through the import URL policy, rejects embedded URL usernames/passwords, and blocks common credential query keys on manifest source URLs. Multi-file direct-url manifests must use a base URL ending in `/` without query strings or fragments; each safe manifest file path is appended by the control plane. Hugging Face manifests must use `https://huggingface.co/...`; per-file source URLs are derived from the repo URL, revision, and manifest path. Direct-url redirects must stay on the original host. Hugging Face redirects may go only to Hugging Face or known HF/CDN hosts. Authenticated downloads reference an encrypted secret in category `model-download`; the runner decrypts the token at claim time, sends it only as an `Authorization: Bearer` header to the original source host, and preserves resume `Range` headers without writing the token, signed redirect URL, manifests, download rows, audit metadata, or logs. The worker writes only to `$B1_DATA_ROOT/models/blobs/.partial`, refuses to overwrite an existing non-verifying target blob, and atomically publishes to `$B1_DATA_ROOT/models/blobs/{sha256}` after per-file size and SHA-256 verification.

Archive-format model blobs are inspected only after content-address verification. The lifecycle code supports zip and tar variants, rejects traversal, symlinks, hardlinks, device nodes, FIFOs, encrypted zip entries, duplicate overwrite paths, denied executable/code extensions, oversized members, excessive member counts, and excessive uncompressed totals. Runtime-view extraction writes only regular files and directories under the resolved view root and never uses archive library `extractall` helpers.

Model removal is staged. Removing a model record moves runtime views to quarantine and leaves authoritative blobs in place. A separate blob-quarantine plan refuses installed records, active job references, blobs referenced by any other model record, symlinked paths, missing files, size mismatches, SHA-256 mismatches, and existing destinations before moving bytes to `$B1_DATA_ROOT/models/quarantine/blobs`. No Control Center path performs permanent blob deletion yet.

Backup restore is limited to alternate restore roots and performs explicit tar member writes instead of `extractall`. It rejects absolute paths, traversal, Windows drive paths, unmanifested files, duplicate file entries, symlinks, hardlinks, device nodes, pre-existing symlinked destinations, and checksum mismatches before reporting a restore test as successful.

Workflow-backed media jobs are not trusted just because they came from Media Studio. The control plane reloads the published workflow record, checks role visibility and dependency readiness, enforces the workflow's model/runtime metadata, rejects parameters outside the declared JSON Schema, validates base64 media fields, caps inline media payloads, and enforces resource limits before queueing the durable job.

Custom ComfyUI node code is fail-closed. Workflow manifests may declare `node` dependencies only with lowercase 40-character git commit pins, and dependency readiness checks those pins against the read-only `$B1_COMFYUI_NODE_PIN_REGISTRY`. Registry entries must use HTTPS repository URLs without credentials, must be explicitly `approved`, and may include dependency-lock SHA-256 metadata so dependency changes are visible before operators publish workflows that require custom code.

The native ComfyUI compatibility catch-all denies internal B1 runtime hooks, ComfyUI Manager/custom-node management prefixes, and install/update/pip/git/snapshot-style mutating paths before proxying. Only core ComfyUI mutating routes and explicitly approved `B1_COMFYUI_TRUSTED_ROUTE_PREFIXES` are forwarded.

Browser authentication is backed by PostgreSQL user records and hashed session tokens. The initial administrator can be created only while no active admin exists, and the generated bootstrap key is required when configured. Session cookies are HttpOnly, SameSite=Lax, secure by default, and time-limited by `B1_SESSION_TTL_SECONDS`. The API rejects unsafe cookie-backed requests unless `X-B1-CSRF` matches the token issued for that session. Bearer-token API clients do not use cookies and are not subject to browser CSRF checks.

Open WebUI does not use the administrator bootstrap key for upstream inference. Bootstrap generates a dedicated internal OpenAI-compatible service key under `$B1_DATA_ROOT/secrets`; Compose passes it to Open WebUI through a local env file, and the control plane stores only its salted hash and bounded service scopes.

Configuration values such as optional remote-provider credentials, model-download tokens, runtime credentials, and integration secrets are stored in PostgreSQL only as AES-GCM envelopes. The encryption key is derived from the generated master key file mounted at `/run/secrets/master_encryption_key`; that file remains outside Git under `$B1_DATA_ROOT/secrets/master_encryption_key`. Admin APIs and Control Center never return plaintext, nonce, ciphertext, or full envelopes. The verify action decrypts server-side and returns only metadata plus `status=verified`. Audit events record public names/categories/key fingerprints only, and the audit redactor still treats any metadata key containing `secret`, `token`, `credential`, or similar terms as sensitive.

Optional external runtime configuration is fail-closed. Remote OpenAI-compatible and generic HTTP adapter base URLs must be HTTPS URLs without credentials, query strings, fragments, malformed ports, relative path segments, or private/loopback/link-local/reserved IP literals. Missing or unsafe URLs mark the adapter `unconfigured` and remove it from alias resolution even when external providers are enabled. Administrators can persist external-runtime rows in PostgreSQL; enabling one requires an explicit external-data acknowledgement, and any API key must be referenced through an active encrypted secret in category `remote-provider`. Remote API keys are decrypted only server-side, sent only as bearer headers to the configured runtime, and omitted from public adapter records, logs, and readiness output.

Resource-policy editing is bounded server-side. Administrators cannot raise the default 12 GiB VRAM or 32 GiB RAM limits from the browser, and controls that would violate the one-GPU scheduler invariant remain fixed at one active GPU pipeline, one ComfyUI job, and batch size one. A later hardware upgrade should first update the environment-defined physical profile, then adjust the persisted policy through Control Center.

Admission controls reject new pressure before it reaches the scheduler or artifact writer. Queue/rate limits are derived from durable PostgreSQL job rows, so a control-plane restart cannot reset an abusive client's counters. Upload and job admission check free filesystem reserve under `$B1_ARTIFACT_ROOT`; an optional artifact-root byte cap performs a safe tree scan that skips symlinks. Administrators may persist bounded overrides from Control Center; each update/reset is audited and included in logical PostgreSQL backups. Queue/rate breaches return HTTP 429, storage breaches return HTTP 507, and idempotent job repeats reuse the original row before quota checks.

Runtime reservation reads and cancellations are owner-scoped for ordinary service clients. The administrator/operator fleet view is exposed only through `/admin/runtime-reservations` with `runtimes:read`, so batch clients can reserve time without gaining visibility into other clients' reservation metadata.

Maintenance mode is administrator-only and persisted in PostgreSQL. Enabling it requires `admin:write` and a reason, writes an audit event, blocks new inference, media upload/job submission, native ComfyUI prompt submission, runtime reservation creation, and job retry paths, and prevents CPU, GPU, and model-download runners from claiming queued work. It does not block cancellation, reads, backups, restore tests, or audit inspection, so operators can drain and validate a controlled update or rollback window without granting arbitrary shell or Docker access.

Update management is intentionally metadata-first and constrained. Only administrators can create update rows, every service image must be pinned by digest, `latest` is rejected, source URLs must be HTTPS without credentials, and stage/promote/health/rollback mutations require maintenance mode. Staging creates a normal constrained backup, records runtime-agent image staging results, writes a checksumed Compose image override under the B1 data root, and records self-test output. Promotion verifies that generated override's expected relative path, SHA-256, service list, pull status, and runtime-agent image-inspection results before recording an operator handoff command; request bodies cannot supply commands or host paths. Rollback delegates only to runtime-agent's predefined allowlisted rollback plan. The update API does not expose arbitrary shell commands, Docker operations, host paths, unpinned images, or environment variables.

Scheduled backups reuse the same constrained control-plane backup path as manual backups. The schedule row stores timing and retention policy only; it cannot supply arbitrary host paths, include/exclude lists, commands, or destinations. PostgreSQL native dumps run through fixed `pg_dump`/`pg_restore` argv lists with credentials supplied through libpq environment variables; database passwords are not placed in shell strings, audit metadata, or manifest fields. Configured backup archive encryption uses chunked AES-GCM with a key derived from the generated master key file, records only public encryption metadata and checksums, and never logs the key. In `encrypted-only` mode, the plaintext archive is removed after encryption and restore requires an independently protected copy of the master key. Scheduled retention deletes only validated direct child backup directories under `$B1_BACKUP_ROOT`, preserving invalid or symlinked entries for operator review.

Source quality gates are part of the security boundary. `make secret-scan` checks committed source for private keys, provider tokens, B1 API-token shapes, and literal secret assignments while allowing generated secret file-path placeholders such as `*_FILE=/run/secrets/...`. `make sbom` emits `artifacts/sbom/b1-ai-hub.cdx.json` from pinned Python requirements, NPM lockfiles, and Dockerfile base images. CI validates that SBOM with the pinned CycloneDX CLI image, runs `pip-audit` for every Python service requirements file, builds both React frontends and all local service images, runs production `npm audit`, and scans the source tree plus built images with the pinned Trivy image. B1-owned runtime/frontend images fail on HIGH or CRITICAL findings. The official Open WebUI wrapper is pinned to an immutable upstream digest and scanned as an uploaded inventory; operators should review that report during update staging rather than masking upstream application findings with local dependency rewrites.

## Roles and Scopes

Initial roles are `admin`, `operator`, `creator`, `user`, and `service`.

`admin` may grant all scopes. Other roles are bounded to their expected operational surface; for example, a `service` client can receive inference, jobs, model-read, and Model Hub sync scopes but cannot receive `admin:write`.

The default Compose configuration sets `B1_DEV_AUTH_BYPASS=false`. Set it to `true` only for isolated local development where bypassing all role checks is acceptable.
